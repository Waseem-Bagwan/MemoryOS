# MemoryOS — How to Run (No Docker Needed)

## What you need
- Node.js 18+ installed
- An OpenAI API key (platform.openai.com/api-keys)
- Your Cognee Cloud dashboard (already set up from screenshot)
- A free Neon account (neon.tech) for Postgres
- A free Upstash account (upstash.com) for Redis

---

## Step 1: Get your Postgres URL from Neon (free)
1. Go to https://neon.tech → Sign up free
2. Create a new project → name it "memoryos"
3. Copy the connection string — looks like:
   postgresql://waseem:password@ep-xxx.us-east-2.aws.neon.tech/neondb?sslmode=require

## Step 2: Get your Redis URL from Upstash (free)
1. Go to https://upstash.com → Sign up free
2. Create a Redis database → region: closest to you
3. Go to database page → copy "REDIS_URL"
   Looks like: rediss://default:password@xxx.upstash.io:6379

## Step 3: Create your .env file
In your project root (where package.json is), create a file called `.env`:

```
PORT=3000
NODE_ENV=development

DATABASE_URL="postgresql://..."        ← paste from Neon

JWT_SECRET="any-long-random-string-here-make-it-long"
JWT_EXPIRES_IN="7d"

REDIS_URL="rediss://..."               ← paste from Upstash

OPENAI_API_KEY="sk-..."               ← your OpenAI key

COGNEE_API_KEY="2c12caa5****"          ← MemoryOS key from your dashboard
COGNEE_TENANT_ID="c0c871f8-6220-4277-8937-3dbbeb8f582f"
```

## Step 4: Install dependencies
```bash
npm install
```

## Step 5: Generate Prisma client + create tables
```bash
npm run db:generate
npm run db:migrate
```
When it asks for migration name → type: init → press Enter

This creates 4 tables in your Neon database:
  users, sessions, memories, decision_logs

## Step 6: Start the server
```bash
npm run dev
```

You should see:
```
✅ Redis connected
🧠 MemoryOS is running
   Port:        3000
   Health:      http://localhost:3000/api/health
```

## Step 7: Test with these curl commands

Open a second terminal and run these one by one:

### Register a user
```bash
curl -X POST http://localhost:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"test@test.com","password":"password123","name":"Waseem"}'
```
Copy the "token" from the response.

### Ingest your first memory
```bash
curl -X POST http://localhost:3000/api/memory/ingest \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer PASTE_TOKEN_HERE" \
  -d '{"content":"I am a TypeScript developer building MemoryOS","sessionId":"session-1"}'
```
You should see a decision like: action: "STORE", reasoning: "...", importance: 0.8

### Test conflict detection (the key feature)
```bash
# First fact
curl -X POST http://localhost:3000/api/memory/ingest \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer PASTE_TOKEN_HERE" \
  -d '{"content":"I live in Mumbai","sessionId":"session-1"}'

# Conflicting fact — watch action become "UPDATE"
curl -X POST http://localhost:3000/api/memory/ingest \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer PASTE_TOKEN_HERE" \
  -d '{"content":"I moved to Bangalore last month","sessionId":"session-1"}'
```

### See the full decision log (explainability)
```bash
curl http://localhost:3000/api/memory/decisions \
  -H "Authorization: Bearer PASTE_TOKEN_HERE"
```

### List all your memories
```bash
curl http://localhost:3000/api/memory \
  -H "Authorization: Bearer PASTE_TOKEN_HERE"
```
